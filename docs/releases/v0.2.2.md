# codex-monitor v0.2.2

## Changes since v0.2.1

- **Interactive installation.** A new setup wizard asks for your Codex directory, client, display mode, automatic status reports and background launcher preferences. It installs dependencies, checks the plugin, and explains how to activate it. Preview the setup with `--dry-run`.
- **Simpler, validated configuration.** MCP tools now expose explicit parameter types and defaults. The new `monitor_validate` tool checks configuration and local prerequisites before starting a workload. Command monitoring can infer its mode and report completion without an output-matching rule.
- **Compact event handling.** The new `monitor_event` tool displays a trigger and its evidence, then combines acknowledgement and final status after the event is handled. The new `monitor_display` tool switches between compact and verbose output per conversation, reducing redundant status and acknowledgement calls.
- **Automatic status reports.** The new `monitor_report` tool and optional Stop/Interrupt hooks show a short summary such as `Monitor · 2 running`. Inactive monitors and historical events stay out of routine output. The skill also guides Codex to clean up obsolete monitors and acknowledge handled events.
- **Optional live status panel.** Supporting MCP Apps hosts can display active workloads, events and recovery status. Codex CLI uses plain-text tool results; it does not render this panel or a separate background-arrival card. Desktop rendering remains unverified.
- **Installation and startup fixes.** Corrected Windows plugin paths, forwarding of custom Codex/monitor directories, and a race when multiple callers start the monitoring service.

Workload monitoring, native callbacks, goal waiting and configurable session recovery from v0.2.1 remain available. Recovery is still opt-in, with a fixed 300-second retry interval and a three-hour incident limit by default.

## Installation

### Requirements

- Node.js **22.22 or newer**; Node 24 is recommended.
- npm and Codex CLI **0.166.0 or newer**, available in your terminal.
- A local Codex installation. No Python or Codex source build is required.

### Install the release package

1. Download [codex-monitor-v0.2.2.zip](https://github.com/EthenJ/codex-monitor/releases/download/v0.2.2/codex-monitor-v0.2.2.zip) and extract it. A [SHA256 checksum](https://github.com/EthenJ/codex-monitor/releases/download/v0.2.2/codex-monitor-v0.2.2.zip.sha256) is also available.
2. Open a normal terminal in the extracted directory containing `install.mjs` and run:

   ```sh
   node install.mjs
   ```

3. Answer the configuration questions and review the installation plan. The wizard handles dependency installation and plugin registration.

To preview your choices without installing:

```sh
node install.mjs --dry-run
```

Alternatively, install from the versioned Git checkout:

```sh
git clone --branch v0.2.2 --depth 1 https://github.com/EthenJ/codex-monitor.git
cd codex-monitor
node install.mjs
```

### Activate the plugin

1. Fully close and reopen Codex CLI or the desktop client.
2. Check `/plugins` and `/mcp`, then ask Codex to call `monitor_display` to verify that the plugin is loaded.
3. If you enabled automatic reports, open `/hooks` and review/trust the **codex-monitor Stop and Interrupt** hooks. Installation alone does not grant hook trust.
4. If the launcher was not started during setup, run the exact bootstrap command printed by the wizard from an external terminal. Run it again after login or reboot; it is not an OS startup service. Use the same Codex and monitor directories as the client.

You can then ask Codex to monitor a command, file or training job. Automatic conversation retries require a separate request in the conversation where you want them enabled.

### Upgrade from v0.2.1

Finish or reconcile existing monitors, waits, recovery and pending events before upgrading. Run `node install.mjs` from the **new v0.2.2 package** and choose to replace the existing codex-monitor installation. The installer preserves monitor state and unrelated Codex settings, and refuses replacement while monitoring is active or unresolved. Reopen Codex and review the updated hooks afterward.

For agent-assisted installation, configuration-file examples and troubleshooting, see the [installation guide](https://github.com/EthenJ/codex-monitor/blob/v0.2.2/codex-monitor/references/installation.md).
