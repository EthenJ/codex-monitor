# codex-monitor v0.2.3

## Changes since v0.2.2

- **Manual goal pause now blocks ordinary monitor callbacks.** Previously a file or command event could start another conversation turn even while the goal was paused. Events now stay local until a native resume update, subject to their existing expiry. Only the selected monitors of an explicitly authorized goal wait may wake its paused goal.
- **Later user actions revoke conditional resume.** A new manual pause, goal edit or interruption takes precedence over an earlier instruction to resume automatically. Repeated pauses within the same second are recognized through native notifications, even when the goal snapshots are identical. Notifications arriving after RPC responses and pauses arriving during state reads are also handled.
- **Cancelled and disconnected waits stop future selected wakeups.** Selected monitors are muted, preventing subsequent events from falling through into ordinary callbacks. Unrelated monitors keep their own delivery policy. A lost connection requires inspection and explicit rearming; it does not silently restore a goal.
- **Clearer, reusable waits.** Equivalent registrations reuse the active wait, and expired historical events no longer block a new one. Tool results distinguish confirmed pause, unchanged goal, confirmed resume and unverified control. The skill tells Codex to end its current turn promptly after confirming a pause.
- **Regression coverage for the actual host.** Isolated Codex App Server tests exercise the full Manager lifecycle: conditional pause/resume, manual pause and resume, manual interruption, and repeated manual pause. Local synthetic model responses avoid user credentials and paid model calls.
- **Windows concurrent startup fix.** Retry a transient lock-directory deletion error within the existing startup deadline. Persistent permission failures still fail, without starting another observer. Native test cleanup also tolerates briefly retained SQLite handles.

Native goal pause stops future goal continuations; it does **not** interrupt the current turn or terminate its tools. Already-submitted callbacks cannot be recalled. The host does not provide an atomic pause/submit/resume transaction, so a user action racing a final write remains a limitation. Recovery defaults remain a fixed 300-second interval and a three-hour incident limit, with separate opt-in authorization.

Validated on Windows with Node 24.22.0 and Codex 0.166.0: **153 tests, 147 passed, six expected platform/hardware skips, zero failures**. [Cross-platform CI](https://github.com/EthenJ/codex-monitor/actions/runs/41289652521) passed all **18 jobs**, including Windows/Ubuntu/macOS Node coverage and the full Ubuntu native suite with networking disabled.

## Installation

Requires Node.js **22.22+** (24 recommended), npm, and Codex CLI **0.166.0+** with a compatible local daemon. No Python or Codex source build is required.

Download and extract [codex-monitor-v0.2.3.zip](https://github.com/EthenJ/codex-monitor/releases/download/v0.2.3/codex-monitor-v0.2.3.zip), then open a normal terminal in the directory containing `install.mjs`:

```sh
node install.mjs
```

The wizard asks for your Codex directory, client, display mode, automatic reports and launcher preferences. It installs dependencies and checks plugin registration. Use `node install.mjs --dry-run` to preview the configuration. A [SHA256 checksum](https://github.com/EthenJ/codex-monitor/releases/download/v0.2.3/codex-monitor-v0.2.3.zip.sha256) is available for the archive.

Alternatively, install from the versioned deployment checkout:

```sh
git clone --branch v0.2.3 --depth 1 https://github.com/EthenJ/codex-monitor.git
cd codex-monitor
node install.mjs
```

After installation:

1. Fully close and reopen Codex CLI or the desktop client.
2. Check `/plugins` and `/mcp`, then ask Codex to call `monitor_display` to verify activation.
3. If automatic reports are enabled, review/trust this version's **codex-monitor Stop and Interrupt** hooks in `/hooks`. Installation alone does not grant hook trust.
4. If needed, run the exact bootstrap command printed by the installer from an external terminal. Repeat after login or reboot; the launcher is not an OS startup service.

For an upgrade, first reconcile active monitors, waits, recovery and unresolved events. Run the installer from the **new v0.2.3 package** and select replacement. The installer preserves monitor state and unrelated Codex settings, and refuses to replace an active installation. Reopen Codex and review updated hooks afterward. Automatic conversation retries still require a separate request in the intended conversation.

See the [installation guide](https://github.com/EthenJ/codex-monitor/blob/v0.2.3/codex-monitor/references/installation.md) for agent-assisted setup and troubleshooting. Codex CLI uses compact text results; rendering of the optional desktop panel remains unverified.
