# Codex Monitor v0.4.0

## Changes since v0.3.0

- **Monitor remote Linux workloads through persistent SSH.** Add
  `transport: {"type":"ssh","host":"gpu-box"}` to `monitor.start` to watch
  existing files, directories, process exit, training inactivity and GPU
  utilization. Connections are shared by SSH profile within the conversation.
  The remote host needs standard shell utilities; no Node.js, Python, plugin
  files, writable home or remote daemon is required. Existing SSH aliases,
  identity files and ProxyJump configuration remain usable.
- **Treat connection failures as events.** New `connection_lost`,
  `connection_unresponsive` and `connection_restored` notifications distinguish
  lost observation from a failed workload. `kind: "connection"` watches a host
  without a workload path. Shared incidents retain each actionable subscriber's
  instructions and notification lifetime, and can release an existing CLI poll.
  Status and hook summaries show `reconnecting` separately from `running`.
- **Bound reconnects and remote sampling.** Reconnect uses approximately
  5/15/30/60-second delays with jitter and a configurable 30-minute incident
  budget. Restoration is reported after 60 seconds of stability. Source identity
  and capabilities are rechecked after reconnect; file/GPU dwell resets across
  observation gaps. Queries have local and remote deadlines, bounded responses
  and directory-entry limits. Oversized or timed-out samples fail their source
  without taking down healthy subscribers. SSH host-key checks remain strict.
- **Make stopping and delivery safer.** Stopping one observer preserves the
  other observers' notifications, releases its dependent wait for reassessment
  and withdraws its event instructions. Cancelled registrations cannot attach
  late observers. The last SSH observer retains its capacity slot until cleanup
  finishes. Final callback preparation rechecks cancellation, acknowledgement,
  expiry and observed goal changes; unhandled failed evidence survives history
  collection.
- **Keep recovery quiet and respect waits.** Plugin waits established during
  asynchronous host reads suspend recovery without disabling it. Active work,
  monitor waits and daemon outages no longer leave an overdue retry driving
  100 ms background checks. Final submission rechecks opt-outs, interruptions,
  host activity and deadlines before spending an attempt.

The eight MCP tool names are unchanged. Existing local monitors continue to
work without `transport`. CLI blocking polls still default to one hour when
`timeout_ms` is omitted. Conversation recovery still defaults to fixed
300-second retries with a three-hour incident limit; SSH reconnect has its own
independent policy. Remote monitoring observes existing workloads and never
takes ownership of or restarts training processes.

## Installation and upgrade

Requires Node.js **22.22+** (24 recommended), npm, Codex CLI **0.166.0+** and a
compatible loaded local Codex daemon. SSH monitoring additionally requires a
local OpenSSH client supporting `ForkAfterAuthentication`, `StdinNull` and
`SessionType`, plus working noninteractive authentication and trusted host keys.
Remote Linux needs `sh`, GNU-compatible `timeout`, `base64 -w 0` and the query
utilities for the selected sources (`stat`, `cat`, `find -printf`, `/proc`, or
`nvidia-smi`).

Download and extract [codex-monitor-v0.4.0.zip](https://github.com/EthenJ/codex-monitor/releases/download/v0.4.0/codex-monitor-v0.4.0.zip),
then run from the directory containing `install.mjs`:

```sh
node install.mjs
```

Alternatively:

```sh
git clone --branch v0.4.0 --depth 1 https://github.com/EthenJ/codex-monitor.git
cd codex-monitor
node install.mjs
```

The wizard asks about the Codex directory, client, display, hook reports,
launcher startup and recovery default. Preview with `node install.mjs --dry-run`.
Before upgrading, reconcile active monitors, waits, recovery and unresolved
events. The installer also refuses replacement while SSH observers reconnect.

Fully exit and reopen Codex. Check `/plugins` and `/mcp`, then ask Codex to
execute `monitor.display`. If reports are enabled, review and trust this
version's Stop/Interrupt hooks in `/hooks`. Use the launcher command printed by
setup when needed, and start it again after login/reboot. Existing observations
are not silently transferred or rearmed during replacement.

See the [installation guide](https://github.com/EthenJ/codex-monitor/blob/v0.4.0/codex-monitor/references/installation.md),
[SSH configuration reference](https://github.com/EthenJ/codex-monitor/blob/v0.4.0/codex-monitor/references/plugin.md#ssh-monitoring)
and [SHA256 checksum](https://github.com/EthenJ/codex-monitor/releases/download/v0.4.0/codex-monitor-v0.4.0.zip.sha256).

## Validation and limits

- Windows: **295 tests, 286 passed, 9 skipped, zero failures**, including real
  SSH, network pause/unpause, stable restoration, source isolation, native
  callbacks, goal waits, hooks and installation.
- Ubuntu 24.04: **295 tests, 280 passed, 15 skipped, zero failures**, as a
  regular user with external networking disabled, including native CLI input
  during a pending MCP call and recovery fault injection.
- Separate internal-network Linux SSH fixtures: **2 passed**, covering direct
  and ProxyJump connections to a runtime-free server with a read-only home.
- Production-only dependency installation and the packaged eight-tool MCP
  execution/resource probe passed. Source and compiled deployment runtime
  consistency, skill validation and whitespace checks passed.

Real NVIDIA hardware remains untested; controlled provider output covers GPU
logic. Snapshot sampling can miss changes between reads or during an outage.
Unusual remote shells, macOS SSH and multi-hop production proxy chains remain
outside the exercised SSH environments. Remote queries stuck in kernel I/O
cannot be guaranteed immediate termination. Host operations are not atomic:
already-submitted callbacks cannot be recalled. CLI remains the primary tested
client; this release does not establish desktop graphical rendering support.

`main` and the release archive contain deployment files only. TypeScript source,
tests, workflows and the detailed review record remain on `develop`. The project
remains MIT licensed.
