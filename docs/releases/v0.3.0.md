# Codex Monitor v0.3.0

## Changes since v0.2.4

- **CLI waits keep the native goal active.** `monitor.poll` holds one MCP call
  pending while external work runs. A monitor event, newly submitted same-thread
  CLI input or finite timeout releases that call without repeated model turns.
  Omit `timeout_ms` for one hour, or provide a custom value up to 24 hours.
  Local input-history sampling defaults to 250 ms; prompt text remains with Codex.
- **A smaller, clearer MCP API.** The eight public tools are `start`, `stop`,
  `event`, `status`, `validate`, `display`, `poll` and `recovery`, under the
  `monitor` namespace. `status` combines summary, active and full-evidence views;
  `event` combines inspection and acknowledgement with `resolution`.
  `stop(target: "wait")` cancels waiting and mutes its selected notifications
  while preserving observers, workload processes and the goal.
- **Recovery is on by default for new operational threads.** First monitor/wait
  use enables `all_failed` recovery: fixed 300-second delay, a three-hour incident
  limit and a separate 24-hour supervisor lifetime. All remain configurable.
  Installation and per-thread opt-outs, manual interruption, host budget/policy
  stops, service restart and uncertain submissions take precedence. It waits for
  Codex's own retries and verifies terminal failure before requesting continuation.
- **More reliable wait ownership and cancellation.** Legacy `mode: "pause"`
  remains available with conditional authorization. Manually resuming the same
  plugin-paused goal preserves its observers and queued evidence. Cancellation
  during preparation cannot attach a late wait; disconnected calls preserve
  observers and hold callbacks until reconciliation. Burst events returned by a
  blocking call stay unhandled until explicitly resolved.
- **Long waits no longer hit a hidden five-minute HTTP ceiling.** Local RPC now
  uses a caller-bounded HTTP request instead of fetch's independent headers
  timeout, with cancellation covering quiet headers and partial responses.
- **Structured timing and clearer documentation.** Event results include elapsed
  wait and observation timing for agent planning without adding it to routine
  user output. The README includes flowcharts for event delivery, blocking waits
  and bounded recovery.

### Tool-name migration

Old `monitor_*` MCP aliases are removed. Replace `monitor_start` with `start`,
`monitor_wait` with `poll`, and the other retained operations with their short
names. Replace standalone `monitor_report` with `status`, `monitor_ack` with
`event(event_ids, resolution)`, and `monitor_cancel_wait` with
`stop(target: "wait")`. Native callbacks now use `monitor.event`; internal
structured envelope types such as `monitor_report` remain stable.

## Installation and upgrade

Requires Node.js **22.22+** (24 recommended), npm, Codex CLI **0.166.0+** and a
compatible loaded local Codex daemon. GPU monitoring additionally requires
working `nvidia-smi`.

Download and extract [codex-monitor-v0.3.0.zip](https://github.com/EthenJ/codex-monitor/releases/download/v0.3.0/codex-monitor-v0.3.0.zip),
then run from the directory containing `install.mjs`:

```sh
node install.mjs
```

Alternatively:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/EthenJ/codex-monitor.git
cd codex-monitor
node install.mjs
```

The wizard explains and asks about the Codex directory, client, compact/verbose
display, hook reports, launcher startup and the recovery default. Use
`node install.mjs --dry-run` to preview. Before upgrading, reconcile active
monitors, waits, recovery and unresolved events; replacement refuses busy state.

Fully exit and reopen Codex after installation. Check `/plugins` and `/mcp`,
then ask Codex to execute `monitor.display`. If reports are enabled, review and
trust this version's Stop/Interrupt hooks in `/hooks`. Start the launcher with
the command printed by setup if needed, and restart it after login/reboot.
See the [installation guide](https://github.com/EthenJ/codex-monitor/blob/v0.3.0/codex-monitor/references/installation.md)
and [SHA256 checksum](https://github.com/EthenJ/codex-monitor/releases/download/v0.3.0/codex-monitor-v0.3.0.zip.sha256).

## Validation and limits

- Windows: **249 tests, 242 passed, 7 skipped, zero failures**, Node 24.22.0 and
  Codex CLI 0.166.0. The current user-installed plugin ran the final regression
  and delivered native completion callbacks.
- Ubuntu 24.04: **249 tests, 244 passed, 5 skipped, zero failures**, Node 24.22.2
  and Codex CLI 0.166.0, as UID 1000 with external networking disabled. Includes
  an actual CLI pseudo-terminal test of input arriving during a pending MCP call.
- Native goal, input/event/timeout/cancellation, recovery/network, installation,
  reduced API and HTTP cancellation suites passed. An isolated production-only
  package installed locked dependencies and passed the eight-tool MCP smoke check.
  Legacy Windows compatibility tests also passed: 115 tests with 18 platform skips.
- [Cross-platform CI](https://github.com/EthenJ/codex-monitor/actions/runs/41405299251)
  passed all 18 jobs, including Node 22/24 on Windows, Ubuntu and macOS and the
  isolated native network/container suite.

Blocking input support is validated for CLI; desktop input and graphical panel
rendering are not established. Windows input-tail/native MCP tests do not replace
an interactive Windows keyboard test. Hardware skips do not establish NVIDIA
hardware coverage. A 310-second real HTTP test verified removal of the observed
five-minute ceiling; a complete one-hour soak was not run. Active-goal elapsed
time can continue during blocking, and host timeout overrides still apply.

The release and `main` contain deployment files only; sources, tests, workflows
and validation records remain on `develop`. The project remains MIT licensed.
