# Codex Monitor v0.4.1

## Changes since v0.4.0

- **Subagent-aware ownership.** Native parent metadata routes new observers into
  one root task service while retaining their creator. Root reports include all
  branches; child operations are restricted to their own subtree. Names remain
  independent between siblings.
- **Concurrent child waits.** Independent children can use blocking `poll`
  alongside the root. A matching child receives its event through the pending MCP
  call; otherwise delivery goes to the root. Shared recovery and optional native
  goal pause/resume remain root-only.
- **Lifecycle handoff.** Closing or completing a child preserves observation and
  hands unacknowledged returned evidence to the root for reconciliation. Event
  bursts stay reserved while a child handles its first result. Previously
  acknowledged evidence is not replayed.
- **Input and stop handling.** Native agent messages, queue changes and new CLI
  input from verified ancestors release pending child calls. Parent interruptions,
  parent/child goal stops, budgets, cancellations and disconnections take
  precedence; message text is never replayed by the plugin.
- **Shared SSH and capacity.** Branches reuse the task's SSH pool and 32 observer
  slots. Connection incidents retain separate creator-scoped event IDs so one
  child's acknowledgement cannot consume a sibling's evidence.
- **Validation and reporting.** Host preflight reports verified routing; child
  recovery changes are rejected. CLI and optional panel reports include creator
  provenance and child wait status. Inactive members are reclaimed without losing
  historical monitor provenance or pruning in-flight registration. Saved reports
  remain explicitly unverified.
- **Lifecycle race fixes.** Stale host responses cannot attach waits or launch
  queued monitors after cancellation, completion or disconnection. Ancestor
  closure releases descendant waits; repeated subscriptions do not interrupt
  an ancestor's active goal wait. Unknown handoffs require reconciliation, and
  delegated handoff persistence failures release the pending call safely.
- **Test maintenance.** Consolidated four obsolete or duplicate cases, extracted
  shared subagent fixtures and added fifteen race regressions. Native fixtures
  distinguish real host behavior from fake-host unit coverage.

The public interface still has eight tools. No new required configuration or
parent thread ID is needed: agents keep passing their own exact `thread_id`.

## Installation and upgrade

Download and extract [codex-monitor-v0.4.1.zip](https://github.com/EthenJ/codex-monitor/releases/download/v0.4.1/codex-monitor-v0.4.1.zip),
then run from the directory containing `install.mjs`:

```sh
node install.mjs
```

Alternatively:

```sh
git clone --branch v0.4.1 --depth 1 https://github.com/EthenJ/codex-monitor.git
cd codex-monitor
node install.mjs
```

The interactive installer explains the configuration directory, client, display,
hooks, launcher and default recovery policy. To inspect the plan first:

```sh
node install.mjs --dry-run
```

Requires Node.js 22.22+ (24 recommended), npm, Codex CLI 0.166.0+ and a compatible
local daemon. Before upgrading, finish or reconcile existing monitors, waits,
recovery and unresolved events. Pre-0.4.1 child services with active or unknown
state are not silently migrated. The installer refuses to replace a busy
installation.

After installation, fully exit and reopen Codex, check `/plugins` and `/mcp`, and
execute `display` to verify activation. Review the upgraded Stop/Interrupt hooks
in `/hooks` if automatic reports are enabled. Start the external launcher using
the installer's printed command if it was not started during setup.

See the [installation guide](https://github.com/EthenJ/codex-monitor/blob/v0.4.1/codex-monitor/references/installation.md),
[subagent behavior](https://github.com/EthenJ/codex-monitor/blob/v0.4.1/codex-monitor/references/plugin.md#subagents),
[SHA256 checksum](https://github.com/EthenJ/codex-monitor/releases/download/v0.4.1/codex-monitor-v0.4.1.zip.sha256)
and [validation record](https://github.com/EthenJ/codex-monitor/blob/develop/docs/design/v0.4.1-validation.md). CLI output remains text;
the host decides whether the optional HTML panel renders.

## Validation

- Windows / Codex 0.167.0: **334 passed, 9 skipped, 0 failed**.
- Ubuntu 24.04 / Codex 0.166.0: **327 passed, 16 skipped, 0 failed**.
- **50 focused subagent tests** passed, including real native spawning, inherited
  MCP calls, message wakeups and the production plugin's shared service.
- Production package: **45 files, 30 runtime modules, 8 MCP tools**. Offline
  production dependency installation, MCP startup and UI resource loading passed;
  source, tests and workflows are excluded.
- [Cross-platform CI](https://github.com/EthenJ/codex-monitor/actions/runs/42470677640):
  **all 19 jobs passed**, including Node 22/24 and legacy Python on Windows,
  Ubuntu and macOS, real SSH/direct/ProxyJump fixtures and native container suites.

Graphical desktop rendering, native macOS Codex host behavior and real NVIDIA
hardware were not validated. The native tests use isolated local providers;
no paid model requests are needed.

`main` and the release archive contain deployment files only. TypeScript source,
tests, workflows and review records remain on `develop`. The license remains MIT.
