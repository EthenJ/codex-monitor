# codex-monitor v0.2

Plugin/package version: **0.2.0**. Git tag: **v0.2**. Previous public release: **v0.1**.

This release replaces the standalone Python skill with a Node.js plugin that observes workloads independently and delivers native tool results to the original Codex conversation. The earlier v0.2/v0.3 preview labels were development milestones, not public release tags.

## Changes since v0.1

- **Node plugin and seven MCP tools.** Start, inspect and stop monitors, wait for events, cancel waits, acknowledge handled events and configure bounded session recovery. TypeScript sources compile to deployment JavaScript; Python is no longer a plugin dependency.
- **Native conversation delivery.** Events use the existing Codex daemon's App Server and `turn/start.toolOutput`, replacing the standalone skill's queued user-message adapter. MCP supplies the control tools; native App Server delivery supplies continuation. The exact original thread must already be loaded.
- **Quiet background observation.** Per-thread services continue across MCP disconnect/reconnect. An external launcher supports independence from the Windows MCP process job. Healthy training progress remains local while the agent works on other tasks.
- **Native goal waiting.** With user authorization, pause the existing goal after independent work is exhausted and resume it when a selected event arrives. Preserve its objective, budget, usage and native interface. Later user edits, cancellation and exhausted budgets take precedence.
- **Bounded session recovery.** After Codex's own retries finish, eligible terminal connection, stream and server failures can trigger opt-in retries with exponential backoff and finite limits. Manual interruption, paused goals, permanent errors and uncertain submissions are not overridden. Recovery continues the conversation rather than replaying shell commands or restarting training.
- **Provider-busy stream recovery.** Handle the observed `stream disconnected before completion: Our servers are currently busy. Please try again in a moment.` terminal error even when Codex 0.166.0 classifies it as `other`. This exact signature is allowlisted; unrelated unknown errors, authentication and quota failures remain ineligible. An isolated real App Server test reproduces the error and verifies one successful recovery after backoff.
- **Workload sensors and watchdogs.** Match command output; observe files/directories and existing process exit; detect sustained inactivity and low NVIDIA GPU utilization. Support startup grace, per-device dwell, hysteresis, AND/OR conditions and optional recovery notifications. Missing GPU metrics remain unknown.
- **Event lifecycle and reconciliation.** Persist evidence and event IDs; suppress duplicate, expired, superseded and acknowledged pending events. Distinguish accepted submission from explicit handling. Restarted services do not blindly rearm observations or replay uncertain actions.
- **Cross-platform fixes.** Preserve UTF-8 across HTTP and output chunks, retain distinct command matches inside debounce, count real file updates even when their notifications are debounced, reject invalid paths, and reconcile bigint/number metadata and delayed native notifications so unchanged files do not reset inactivity. Improve cancellation, proxy and owned-process cleanup.
- **Deployment-only distribution.** Ship compiled runtime, production dependency manifests, plugin metadata, skill instructions, README and license. Keep source, tests, workflows, legacy Python helpers, development dependencies and validation reports on `develop`.

## Upgrade

Requires Node.js **22.22+** (Node 24 recommended) and a compatible local Codex CLI/daemon; native integration was validated with **Codex 0.166.0**. NVIDIA checks additionally require `nvidia-smi`. No Codex source build or model API key is required.

Stop old observers and disable the v0.1 standalone skill before loading the plugin. Stop monitors/waits/recovery and the launcher before replacing an installed preview. Remove the old plugin with `codex plugin remove codex-monitor@codex-monitor` when applicable. Install the complete deployment directory:

```text
npm ci --omit=dev
npm run bootstrap
codex plugin marketplace add .
codex plugin add codex-monitor@codex-monitor
```

Run bootstrap from an external terminal, then restart Codex. Rerun bootstrap after login/reboot; it is not an OS service. Old monitor state is not automatically migrated or rearmed. Register the required observations again. Stopping a watchdog preserves the existing training process; stopping an owned command terminates its owned process tree.

## Validation and limits

Windows source validation with native host tests enabled passed **76 tests: 72 passed, four expected skips**. The skips are the opt-in physical GPU test and three POSIX provider fixtures. Release-specific CI and deployment-install evidence are recorded in the release pull request.

Earlier Ubuntu hardware checks covered two RTX 4090 D GPUs: selectors, quiet sampling and a diagnostic threshold/recovery cycle, including native GPU-event delivery. This does not establish real idle-to-loaded training recovery, distributed training or driver-outage recovery on hardware. Native network fixtures cover HTTP 503, broken response streams and no retry after manual interruption using isolated Codex homes and synthetic loopback providers.

Delivery remains subject to Codex scheduling: immediate tool preemption, atomic goal-check-and-start and exactly-once execution are not guaranteed. Submitted results cannot be recalled. File observations compare metadata rather than content hashes. POSIX SIGKILL cannot run userspace descendant cleanup. Stall heuristics require investigation and do not authorize an automatic training restart.
