## Recovery changes

- Replace exponential backoff with a fixed **300-second interval** after each eligible failure. Configure `retry_interval_ms` to change it.
- Stop submitting retries after **three hours per failure incident**. Configure `max_elapsed_ms` to change the window. The window includes retry execution and daemon outages; it is checked again after host reads before submission. It does not kill an already running turn.
- Derive the default attempt cap from the time window and interval (36 with defaults), removing the earlier five-attempt cutoff. `max_attempts` remains configurable. The time deadline is strict: at most 35 retries fit before three hours with immediate failures, and real execution time can reduce this number.
- Add explicit `retry_mode: "all_failed"` for users who authorize retries of unlisted errors. Unknown or missing error details, authentication failures and rate limits qualify once Codex has recorded a terminal failed turn. Default `transient` mode keeps the existing allowlist.
- Preserve manual interruption, goal pause/edit/budget protections, explicit host budget/usage/policy error stops, quiet plugin waits and uncertain-write handling. Recheck error eligibility before writing. Recovery continues the same conversation through native tool output and does not blindly replay commands or restart training.
- Retain compatibility for `base_delay_ms` as an alias for the fixed interval. `max_delay_ms` is accepted for validation but no longer causes exponential backoff. Existing explicitly configured values are not silently changed.

## Configuration

For an authorized broad retry policy, call `monitor_recovery` with the current thread ID and the user's actual authorization:

```json
{
  "thread_id": "<current CODEX_THREAD_ID>",
  "enabled": true,
  "authorization": "<actual user instruction authorizing session retries>",
  "retry_mode": "all_failed",
  "retry_interval_ms": 300000,
  "max_elapsed_ms": 10800000
}
```

The independent supervisor lifetime remains 24 hours by default. Completed turns reset the incident while enabled; manual interruption and exhausted limits require explicit re-enabling. Changing the package does not enable recovery on any live conversation. See the [full recovery contract](../../codex-monitor/references/plugin.md#session-recovery).
