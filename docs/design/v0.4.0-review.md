# v0.4.0 SSH review

Reviewed locally on 2026-11-07. All findings below were corrected in the working
tree. No commit, push, release or replacement of the installed plugin was performed.

## Findings and corrections

| Priority | Trigger and impact | Correction |
| --- | --- | --- |
| High | On Linux, `path === path.posix`. Remote directory validation therefore applied local state-directory protection and rejected valid remote roots such as `/work` or `/`. Reproduced in the Ubuntu container before the fix. | Filesystem ownership is explicit. Remote normalization skips local state comparisons; local protection remains enforced. |
| High | SSH loss while a new subscription was preparing could leave its start pending for the entire reconnect budget. A queued or disconnected caller could also attach an observer after abandoning the request. | Fail unready subscriptions promptly on loss; bound registration separately; propagate MCP/HTTP cancellation through the registration queue and preparation. Existing observers retain reconnect behavior. |
| High | Reconnect budget checks ran only between attempts. An attempt started near the deadline could exceed the budget while stuck in its handshake. New subscribers were also accepted during that attempt. | An incident timer bounds in-flight attempts; reject new subscriptions until the connection has actually recovered. Healthy stabilization is still allowed beyond a shorter reconnect budget. |
| High | An oversized directory/GPU response was classified as a fatal protocol error, terminating every subscriber sharing that session. | Discard the oversized frame within the finite request deadline and fail only its source. Malformed framing or a missing completion still fails the transport. Avoid a repetitive base64 regex on large valid frames. |
| High | After an observation gap, file dwell started before the new baseline finished reading. A slow baseline could immediately report a training stall using time that was not continuously observed. | Restart health timing after acquiring the baseline; retain its fresh GPU sample and emit no stall/recovery transition from the gap itself. |
| Medium | Remote GPU commands ran in the login directory, and GPU cache keys ignored workload directories. Relative provider paths could fail or another workload's sample could be reused. | Run the provider in the remote workload directory; include it in the cache key. |
| Medium | SSH preflight accepted zombie/dead PIDs that registration rejected. A PID exiting between existence check and stat read could be reported as a read error. | Apply the same running-state requirement in preflight; acquire stat first and distinguish a disappeared PID from a remaining but unreadable process. |
| Medium | Shared incidents inherited one representative's `event_ttl_ms`, potentially discarding another subscription's evidence early or retaining it too long. | Group subscriptions by notification lifetime, preserving deduplication and independent expiry. |

Additional checks covered host-key/authentication rejection, shell quoting,
special filenames, persistent-session reuse, selected-poll wake routing, cancellation,
muted subscriptions, observer cleanup, native goals, hooks and deployment contents.
SSH guard errors now identify the required connection loss/unresponsive notifications.

## Follow-up review

The second pass added reproductions for shared waits, withdrawn actions, mixed
sampling rates and shutdown accounting. Each initially failed against the prior
runtime and passed after the correction. It also exercised actual ProxyJump
transport and conflicting SSH profile settings.

| Priority | Trigger and impact | Correction |
| --- | --- | --- |
| High | Stopping one observer during a shared wait called the wait-wide cancellation path, muting remaining observers. | Release the dependent wait for reassessment, preserving other notifications and the goal. Both CLI blocking and authorized pause/re-wait paths are covered. Explicit wait cancellation retains its original mute policy. |
| High | A shared event retained the cancelled representative's instructions and did not distinguish cancelled recipients from actionable ones. | Use one event projection for inspection and blocking results. Expose per-recipient actionability and omit withdrawn/settled instructions while retaining evidence. |
| High | A slow GPU interval dominated gap detection for a fast file watcher, allowing missing observations to count as a file stall. | Measure gaps against the fastest enabled source; remove no-op metadata ticks for GPU-only subscriptions. |
| Medium | The final SSH observer released its slot and advertised stopped before SSH cleanup completed. Repeat stop calls could also return early. | Keep the slot and stopping state until owned cleanup completes. Await pending process creation, previously disconnected sessions and repeated stop operations. Registration failure also awaits sensor cleanup. |
| Medium | Existing host profiles could request backgrounding, null stdin or no command session, preventing the persistent protocol from working. | Set explicit foreground/input/command-session options. Real Windows and Linux tests supply conflicting profile values; a containerized ProxyJump path verifies retained routing and authentication. |

The required foreground/input/session options follow the
[OpenSSH configuration contract](https://man.openbsd.org/ssh_config.5). Local
clients tested here include OpenSSH for Windows 9.5p2 and the Linux fixture's
OpenSSH client. Older clients must support the documented options.

## Third-pass review

Three new regression cases failed before these corrections and passed afterward:

| Priority | Trigger and impact | Correction |
| --- | --- | --- |
| High | Gap detection ran only before sampling. If the local process paused while a file/GPU query was outstanding, its late response could establish a false training stall. | Recheck continuity after awaited reads, before interpreting process/file events or health dwell. Start fresh dwell after the completed observation. Both file and GPU suspension cases are covered. |
| Medium | SSH watchdogs accepted `debounce_ms` but ignored it, producing repeated file notifications and potentially reaching `max_events` earlier than intended. | Apply bounded per-path notification debounce while updating progress for every observed write. Deletion remains visible and clears suppression for recreation; missing files do not count as progress. |

GPU scheduling now measures the next interval from the completed observation,
avoiding catch-up queries after slow samples. Configuration documentation also
distinguishes workload commands from read-only SSH preflight queries, and local
preflight failure from remote readiness failure during registration.

## Fourth-pass review

This pass examined the shared delivery/recovery path used by SSH incidents and
local observers. Eleven initial reproductions failed before correction. Added
follow-up checks cover normal mixed-batch delivery and clearing overdue retries.

| Priority | Trigger and impact | Correction |
| --- | --- | --- |
| High | The final loaded-thread RPC happened after event eligibility and retry authorization checks. Stops, acknowledgements, manual goal pauses, recovery opt-outs or interruptions during that RPC could still start another turn. | Prepare the payload synchronously after the final awaited host read. Recheck cancellation, goal/wait ownership, recipient eligibility, retry epoch and observed host activity immediately before writing. Attempts are charged only when a retry is actually submitted. Unaffected events in a mixed batch remain deliverable. |
| High | An event could expire during goal verification or the final host check yet still be submitted. | Reconcile expiry at the final dispatch boundary; never mark an expired event as sending. |
| Medium | At the 256-event limit, history collection treated failed deliveries as disposable even though they still required inspection. | Reclaim only explicitly settled states. Keep failed and uncertain evidence until it is reconciled; retain the bounded-capacity behavior. |
| Medium | Starting new work or entering a monitor wait left an overdue retry timestamp in place, reducing background checks to the 100 ms minimum. | Clear obsolete retry deadlines while observing active work, waiting or invalidating a prepared retry. A later eligible failure must establish its configured backoff again. |

These guards close locally observed races before submission. They do not create
an atomic compare-and-start transaction with Codex or recall a write already sent.
Deterministic host fixtures inject each change during the last read; native
integration suites verify the actual bridge and tool-result path.

## Fifth-pass recovery review

Two new tests reproduced additional ordering and scheduling failures before
the correction, then passed:

- A monitor wait established while recovery was reading host snapshots could
  cause its plugin-owned goal pause to disable recovery. Recheck waiting after
  asynchronous reads before evaluating terminal goal state.
- An overdue retry combined with daemon read failures scheduled transport-only
  checks every 100 ms. Host outages now retain the configured observation
  interval without resetting the retry deadline, attempts or incident budget.
  The regression also verifies a single eligible retry after connectivity returns.

## Sixth-pass fault isolation and release review

Added a real SSH regression for timed-out remote queries and replaced directory
roots. It verifies remote query child cleanup, source-specific errors, continued
observation by other subscribers and reuse of the same healthy connection.
The installer busy-state test also covers reconnecting observers.
Direct and ProxyJump Linux fixtures were rerun for the final candidate.

## Remaining validation boundaries

No additional blocker was found in the reviewed paths. This does not establish
the absence of defects in other environments.

- NVIDIA behavior uses controlled provider output; real GPU/driver validation remains.
- macOS SSH clients, multi-hop production proxy chains and unusual server shell
  startup files were not exercised. Direct and one-hop ProxyJump Linux fixtures
  have passed; these do not establish compatibility with every production topology.
- Snapshot sampling still cannot recover transient events during a disconnect;
  continuous dwell is reset across missing observations.
- Closing local SSH cannot guarantee immediate termination of a remote query in
  uninterruptible kernel I/O. Remote and local deadlines bound ordinary cases.
- CLI rendering/callback behavior remains dependent on the supported Codex host;
  this change does not establish new desktop rendering support.
- A host change not yet delivered to the plugin can still race an already-sent
  callback. Submission and goal mutation are separate host operations.
