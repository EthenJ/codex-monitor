# v0.4.1: subagent implementation

The [subagent reference](../../codex-monitor/references/plugin.md#subagents)
defines user-visible ownership, scope, waits, handoff and upgrade behavior.
The public interface remains eight tools; callers pass their own thread ID.

## Components

| Component | Responsibility |
| --- | --- |
| `ancestry.ts` | Resolve native parent metadata, reject cycles/conflicts, persist root routes and reject unsafe legacy migration |
| `delegation.ts` | Verify loaded members, lease scoped waits, reserve child delivery and project subtree snapshots |
| `manager.ts` | Own task sensors, evidence, capacity, SSH pool, root waits and recovery |
| `service.ts` / `server.ts` | Route MCP requests to the owner, enforce subtree access and root-only policy |
| `report.ts` | Follow verified saved routes for read-only live/historical reports |

Ancestry is never inferred from a fork or shared session ID. Saved routes include
intermediate ancestors so their hooks can see descendant work before their first
monitor call. Previously verified scopes remain available for cleanup during an
outage; new work requires live verification. Local tokens and caller UUIDs are
not a security boundary against code running as the same OS user.

## Concurrency invariants

- The root owns observers; a pending child call leases delivery only. Independent
  child waits may coexist with the root wait; overlapping child leases cannot.
- Registration and wait preparation retain a member/activity lease across async
  host reads and serialized startup. Stops/disconnects invalidate stale work.
  Service dispatch leaves this verification inside the operation's lease.
- An old failed verification may remove only its own cache entry, never a newer
  successful verification. Descendants reuse verified ancestor subscriptions to
  avoid replaying goal snapshots into an active ancestor wait.
- Initial no-goal snapshots are not stops. During preparation, intervening goal
  notifications are checked against read snapshots. Accounting stays quiet;
  goal edits, pauses and exhausted budgets release or refuse waits.
- Readiness is recomputed after host reads. Thread scope admits later sources;
  selected scope stays narrow. New sources must retain live error/expiry guards.
- Final evidence selection is synchronous. Root and child paths respect branch
  reservations until acknowledgement, expiry or lifecycle handoff.

## Handoff and failure boundaries

Returning evidence sets `delivery_thread_id` and records the child turn; it does
not acknowledge completion. Later events in that branch remain reserved while
unrelated branches continue. Matching terminal lifecycle notices hand unresolved
returned evidence to the root with `handoff.previous_delivery: unconfirmed`.
Old-turn notices cannot release newer waits. Ancestor closure releases descendants.

Disconnect during handling marks returned evidence unknown for reconciliation;
it is never automatically replayed. If persisting a delegated release fails,
the pending call still resolves as interrupted, selected evidence becomes unknown
and callbacks are held. This protects that boundary, not every filesystem failure.

Shared SSH incidents are partitioned by creator and evidence lifetime while
retaining a shared connection ID. One branch cannot acknowledge another's incident.
Service/installer idle checks include delegated activity. Inactive members are
reclaimed only when no live/unknown work, unresolved delivery or preparation lease
requires them; provenance remains on records.
